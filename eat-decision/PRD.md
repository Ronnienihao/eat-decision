# 吃饭极限二选一 — 产品需求文档 v0.4

> 状态：草稿 | 最后更新：2026-05-12

---

## 一、产品概述

**产品名称：** 吃饭极限二选一
**平台：** 微信小程序
**后端：** 腾讯云服务器（自有）+ Node.js / Python 后端服务
**核心玩法：** 通过 5 轮偏好筛选 + N 轮菜品 PK 擂台赛，帮助选择困难的用户决定今天吃什么。

---

## 二、完整游戏流程

### 阶段一：偏好筛选（5 轮）

**启动引导文案（小字，全程显示于页面顶部）：**
> 遵从直觉选择

---

#### 第 01 题：核心大类（二选一）

> 你今天想吃哪种？

- A. 中国菜
- B. 异国料理

---

#### 第 02 & 03 题：属性偏好（2 轮二选一）

从以下 7 组对立属性中**随机抽取 2 组**，每组二选一。

| 组号 | 选项 A | 选项 B |
|------|--------|--------|
| 组 1 | 重口浓郁 | 清淡原味 |
| 组 2 | 管饱正餐 | 轻食/代餐 |
| 组 3 | 肉食主义 | 多点蔬菜 |
| 组 4 | 30¥内搞定 | 可以 30¥以上 |
| 组 5 | 无视卡路里 | 严格控卡党 |
| 组 6 | 热菜 | 冷餐 |
| 组 7 | 15分钟吃完 | 我要慢慢品味 |

---

#### 第 04 题：地域盲盒（三选一）

根据第 01 题结果，从对应池中随机掉落 3 个选项（三选一）。提供一次「换一组」机会，可重新随机掉落 3 个选项。

**池 A（中国菜）：** 广东菜、川湘菜、北方硬菜、江浙本帮、云贵酸辣

**池 B（异国料理）：** 日式料理、韩式料理、美式快餐、经典西餐、东南亚菜

---

#### 第 05 题：烹饪方式（三选一）

从全池随机掉落 3 个选项（三选一）。提供一次「换一组」机会，可重新随机掉落 3 个选项。

> 爆炒、清蒸、慢炖、红烧、砂锅、凉/热拌、酥炸、煎烤、烘焙、生食、熬煮、冷餐、卤制、腌/熏制

---

### 动态跳题规则

每轮选完后，系统实时查询当前条件下的备选菜数量，不足 **30 道**则跳过剩余轮次直接进入 PK 阶段。

| 轮次结束后 | 备选 ≥ 30 道 | 备选 < 30 道 |
|-----------|------------|-------------|
| Q01 | 继续 Q02 | 继续 Q02（Q01 必问）|
| Q02 | 继续 Q03 | 跳过 Q03，进 Q04 |
| Q03 | 继续 Q04 | 跳过 Q04，进 Q05 |
| Q04 | 继续 Q05 | 跳过 Q05，直接进 PK |
| Q05 | 直接进 PK | 直接进 PK |

进入 PK 前显示提示语：
> *「根据你的口味，找到 X 道菜，开始决斗！🔥」*

---

### 阶段二：菜品擂台 PK

**前置标签展示（画面顶部常驻）：**
> 中国菜 · 热菜 · 重口浓郁 · 川湘菜 · 爆炒

**PK 轮数规则（动态）：**

| 候选菜品数量 | PK 轮数 | 说明 |
|------------|---------|------|
| ≥ 8 道 | 7 轮 | 标准模式 |
| 2 ～ 7 道 | 菜品数 - 1 轮 | 缩短赛程 |
| 1 道 | 0 轮，直接胜出 | 命中注定 |
| 0 道 | 特殊兜底 | 见下文 |

**PK 规则：** 上一轮胜者直接晋级迎战下一挑战者，最终存活菜品 = 今日口粮 🏆

---

### 特殊情况：筛选结果为 0 道菜

> 有 **0 道菜** 适合你。
> 该结果产生概率：**0.0001%**
> 你成功筛出了宇宙最难伺候的嘴。

附按钮：「再来一局」（重置所有筛选条件）

---

### 阶段三：结果页

- 展示终极赢家菜名 + 推荐语（来自数据库 `推荐语` 字段）
- 提供「再来一局」和「保存结果」入口
- 分享入口（见分享功能章节）

## 三、催促提示系统（防纠结机制）

| 停留时长 | 提示类型 | 参考文案 |
|---------|---------|----------|
| 进入页面（常驻小字） | 引导语 | 遵从直觉选择 |
| 停留 6 秒 | 轻提示（Toast） | 别想了，胃比脑子诚实 |
| 停留 10 秒 | 气泡弹出 | 你已经盯着它 10 秒了！饿着肚子做决定会更痛苦 |

**规则：** 每页每次进入只触发一次；10 秒气泡带「好好好我选了」关闭按钮。

## 四、用户体系与数据

### 登录方式

- 微信一键授权登录（获取 openid）
- 不做密码注册，不强制绑定手机号
- 首次进入引导授权，用户可拒绝（拒绝则无法使用保存/历史功能，游戏本体不受影响）

### 数据保存逻辑

- 游戏结束后，用户**主动点击「保存结果」**才上传数据
- 不点保存则不存储任何数据（尊重隐私）
- 每条记录保留 **30 天**，到期自动清理

### 存储内容（每条记录）

```json
{
  "openid": "用户标识",
  "date": "2026-05-04",
  "result": "剁椒鱼头",
  "tags": ["中国菜", "重口浓郁", "热菜", "川湘菜", "爆炒"],
  "rounds": 7,
  "slowest_round": 3,
  "created_at": 1746300000
}
```

> **数据最小化原则：** 只存游戏结果和选项标签，不存设备信息、IP、位置。隐私政策须在小程序说明（微信审核要求）。

### 历史回顾页

- 日历或列表形式展示近 30 天的历史结果
- 展示每次的菜名、日期、筛选标签
- 满 **7 条**数据后解锁「我的口味报告」入口

## 五、饮食分析功能（口味报告）

> ⚠️ 本章节为初步方向，具体分析维度待产品方确认后补充。

### 解锁门槛

| 数据量 | 解锁内容 |
|--------|--------|
| ≥ 7 条 | 基础口味报告（偏好标签分布） |
| ≥ 30 条 | 完整报告（含健康建议方向） |

### 初步分析维度方向

**偏好统计（基础）**
- 重口 vs 清淡比例
- 肉食 vs 蔬菜倾向
- 最常选的菜系 TOP 3
- 消费倾向（30¥内 vs 30¥以上）
- 生活节奏推断（速食 vs 慢食比例）

**健康建议方向（待细化）**
- 根据菜系/烹饪方式推断饮食结构（如：川湘+爆炒偏多 → 提示高油高盐）
- 蔬菜/肉食比例失衡提示
- 冷餐/热菜偏好与季节健康建议
- *(具体建议文案、营养数据库接入方式待产品方确认)*

**趣味数据**
- 你的「签名菜」（出现频率最高的赢家）
- 最难抉择奖（停留时间最长的那轮）
- 「宇宙最难伺候」徽章（触发过 0 道菜兜底）

## 七、视觉设计规范

### 配色系统

| 色彩角色 | 色值 | 用途 |
|---------|------|------|
| 米色（背景） | `#FAF7F2` | 页面底色 |
| 橙色（主题色） | `#FF6B35` | 按钮、高亮标签、CTA |
| 深灰（文字） | `#2D2D2D` | 标题、正文 |
| 浅灰（辅助） | `#9CA3AF` | 提示语、次要文案 |
| 白色（卡片） | `#FFFFFF` | 卡片背景 |

### 卡片设计

- 圆角：`border-radius: 24rpx ~ 32rpx`
- 阴影：`box-shadow: 0 4px 20px rgba(0,0,0,0.08)`
- 留白：卡片内 padding 充足，8pt 网格系统

### 平面设计四大原则

| 原则 | 实践方式 |
|------|----------|
| 对齐 | 文字/图标统一对齐方向，禁止随意混用 |
| 对比 | 橙色 CTA 与米白背景强对比；深灰标题 vs 浅灰注释 |
| 重复 | 卡片样式、按钮圆角、字号层级全局统一 |
| 亲密 | 相关元素紧密分组，无关元素保持距离 |

### 格式塔原则

- **接近性**：菜名与描述放在同一卡片
- **相似性**：PK 两张候选卡片等大等样，橙色高亮选中态
- **连续性**：进度指示器线性排列，引导视线左→右
- **封闭性**：卡片边框+圆角+阴影形成封闭感

### 动效设计

| 场景 | 动效 | 参数 |
|------|------|------|
| 卡片出现 | fade-in + 上移 | 300ms, ease-out |
| 点击选择 | 选中卡缩放弹起，未选卡淡出 | scale 1→0.96→1.04, 200ms |
| 页面切换 | 水平滑动 | 350ms |
| 标签进入 | stagger 错落弹入 | 每标签间隔 80ms |
| 结果揭晓 | 模糊→清晰 + 轻微放大 | blur 8px→0, scale 0.9→1 |
| 催促提示 | bounce 轻弹 | 不打断操作流 |

## 八、技术架构

### 前端
- 微信小程序原生框架 或 Taro（待定）
- 飞书多维表格作为菜品数据源（只读，通过后端 API 代理访问）

### 后端
- 部署于**腾讯云服务器（已有）**
- 语言：Node.js / Python（待定）
- 数据库：MySQL 或 MongoDB（待定）
- 接口：RESTful API，微信登录鉴权（code2session）

### 核心 API 设计（草稿）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/auth/login` | POST | 微信 code 换 openid，返回 token |
| `/dishes/filter` | POST | 传入 5 个标签，返回候选菜品列表 |
| `/records` | POST | 保存今日结果 |
| `/records` | GET | 获取用户历史（近 30 天） |
| `/analysis` | GET | 获取口味报告数据 |
